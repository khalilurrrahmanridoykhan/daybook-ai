Bangladesh EWARS is a national disease-surveillance platform Ridoy developed and supported for IEDCR, providing real-time monitoring, predictive analytics, outbreak simulations, and data-driven public-health decision support. It runs in production at ewars.iedcr.gov.bd.

The BRAC Microstratification Data Collection System is a production village-level malaria surveillance system Ridoy led development and design for, delivered with MORU and GroupMappers on the CommuniPlan platform for BRAC. It covers 11,448 villages across 5 districts, converting BRAC's Excel-based reporting into a web data-entry grid with a four-stage data-quality workflow (Not Submitted -> Pending Approval -> Approved -> Rejected), GPS-referenced village data in English and Bangla, and LLIN stock tracking.

The Prohori FHIR-native Disease Surveillance Registry is a complete end-to-end HL7 FHIR R4 field case registry for dengue and malaria: a .NET 8 + Firely SDK write API turning field-visit submissions into atomic FHIR transaction Bundles, a React 19 surveillance dashboard reading FHIR directly, and a ProhoriPatient conformance profile authored in FHIR Shorthand. The final phase conformed the resource model to Bangladesh's national BD-Core-FHIR-IG v0.4.6; the generated Bundle validated with 0 errors and was accepted by the live DGHS government FHIR sandbox. The work also surfaced and documented a real defect in BD-Core 0.4.6 (an empty required ICD-11 diagnosis ValueSet).

The AMR Stewardship Briefing API is a FastAPI service that reads live compliance data from an AMR Stewardship Log DHIS2 app and returns deterministic compliance statistics alongside an LLM-narrated briefing generated via Claude's forced tool-use -- the model is constrained by its system prompt to only narrate the given statistics, never invent a figure or render an independent clinical judgment. A later addition, the "why was this flagged?" endpoint, added a RAG layer: retrieval over a small curated WHO AWaRe reference corpus plus the facility's own live formulary, with a citation-grounding guardrail that rejects any model response citing a document it wasn't actually given.

Ridoy has also built four native DHIS2 applications: a FHIR Sync Console (a FHIR-to-DHIS2 Immunization Bridge control panel), a Data Share Hub (scoped, revocable external API data sharing), a Data Quality Auditor (metadata-driven RDQA-aligned audits), and the OneHealth Intelligence Platform, an open-source disease-surveillance and early-warning research implementation for Bangladesh covering dengue, measles, HPAI, Nipah, and more, with a mandatory human-approval gate before any DHIS2 write.

Ridoy AI is his own self-hosted, open-weight personal AI assistant -- streaming chat, persistent memory, RAG grounding, and tool-use, running entirely on his own infrastructure with no data sent to any third-party AI provider.
